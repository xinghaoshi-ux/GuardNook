# GuardNook 0.4

macOS 顶部悬浮面板：查看 Claude / Codex 网络状态，按需启用 Claude 固定出口守护，提供环境检查、修复记录和运行日志。需要 macOS 15+，支持 Apple 芯片和 Intel。安装包包含所需运行组件。

## 安装与首次使用

打开 DMG，将 GuardNook.app 拖入应用程序。跨电脑运行时请按系统提示确认文件来源。首次使用向导提供两种方式：

- **基础监测**：查看本机网络与可达性，保留现有系统设置，不接入固定出口保护。无需节点或目标 IP。
- **固定出口守护**：连接自己的代理客户端，选择具体节点，确认出口，安装规则后持续验证。异常时关闭受保护通道。GuardNook 不提供节点或订阅。

首页保留可选的待办、笔记与服务状态组件；详细保护状态、环境检查和节点配置位于守护与专线页。待办、笔记、应用启动器可在设置中开启。

Codex 的面板探测跟随当前系统网络；不核对 Claude 的固定出口 IP。配置内网例外时，OpenAI 域名默认沿用普通网络分流与 DNS，不绑定公司 VPN 接口或单独固定附件出口。显式选择 `openaiRouting: "intranet"` 才保留旧版专用内网路由；公司域名、公司网段及办公应用的例外独立保留。

启用公网 TUN 分流且上游使用 UDP 传输时，可通过 `kernelProcessPath` 指定代理内核的完整可执行路径，避免内核自身的 UDP 上游再次进入 TUN 并被阻断。此例外仅匹配内核路径、TUN 和 UDP，放在 Claude 保护规则之后；不放开应用的 UDP，也不改变 Codex 的出口策略。

## 连接向导

1. 选择使用方式。
2. 选择客户端，自动尝试已知本机控制接口。Clash Verge Rev 提供专门适配；其他 Mihomo 客户端通过标准本机 HTTP / Socket 接口连接。不支持的内核仅可使用基础监测。接口需本机可访问；密钥由用户填写，不读取其他客户端凭据。
3. 选择具体节点。先在代理客户端为 Claude 选择该路径，再运行三次检测；每次均核对连接确实经过所选节点。不会改动已有代理组选择。三次出口不一致或链路不符时不创建已验证结果。已有守护阻断、代理端口认证等情况可能无法探测，可明确选择“手动填写出口”，保存后仍需实时验证。
4. 预览固定出口、TUN 要求与将创建的规则/网关，确认后保存。已有全局扩展脚本时，选择加入 GuardNook **之前**的原始脚本，避免覆盖内网或其他应用规则。
5. 新接入需在代理客户端导入生成的脚本并重载，随后点击“启用保护并验证接入”。保存配置不代表保护已生效。匹配的原有独立守护可经过身份与规则校验后连接；不会重复启动或改变其手动阻断状态。

首次守护设置默认要求 TUN，可显式调整。未要求 TUN 时，保护仅覆盖确实经过守护规则的流量，绕过代理的请求不在保护范围内。出口检测记录五分钟内有效；更改节点、控制接口、固定上游或出口后需重新确认。目标不会随节点切换自动追随。

Clash Verge Rev 可持久化 TUN 开关；其他 Mihomo 客户端的 TUN 修改仅影响当前内核运行状态，持久化设置需在对应客户端完成。自动识别只尝试已知本机端点，不扫描网络。其他客户端的规则导入与重载方式需按其界面操作，不承诺所有 Mihomo 外壳均已验证兼容。

## 环境检查、修复与恢复

通用模板首次记录本机实际地区、语言、时区和活动网络服务，国家默认不限。地区、语言、IPv6 和 Fake-IP 状态作为偏好/诊断显示；固定出口、网关、规则等仍按实际守护配置验证。TUN 是否为启动条件统一读取守护配置的 requireTun。

严格模板将用户选定的国家、时区、地区、客户端语言、关闭 IPv6 与 Fake-IP 基线加入启动条件。旧版已有基线按原严格行为保留，不在升级时放宽。

支持 Wi-Fi、有线及自定义命名的网络服务，在基线设置中选择 IPv6 操作目标。仅对已明确选择的服务应用更改；缺少完整手动 IPv6 参数时拒绝修复，避免无法恢复。

“修复”先预览原值与目标值，默认只选中阻塞项目。确认后先保存恢复点，再执行并读取系统值核对。部分失败会显示结果并保留恢复点，未执行项目保持原样。时区和 IPv6 可能需要管理员验证；语言修改需要重启 Claude。

“更改记录与恢复”按新到旧恢复，区分已执行、部分执行、部分恢复与已恢复。发现外部更改时保留记录并停止覆盖。恢复 TUN 关闭状态前，若保护策略要求 TUN，会先将受保护选择器置为 REJECT。旧版环境备份保留在原目录，新版可恢复记录位于 environment-backups-v2。

HTTP 403/429 代表已连接但有限制；API 401 不证明权限通过。STUN 没有响应保持未知，不能据此宣称没有泄漏。Fake-IP 不是所有有效 DNS 配置的必要条件。ASN 仅显示运营商信息，不能证明住宅 IP 或账号安全。匿名探针不验证账号登录，也不代表实际浏览器没有旁路。

## 登录数据

### 首页用量监测

首页在待办/笔记下显示 Codex、Claude 和公司 Coding Plan 三张独立卡片。默认每五分钟查询，手动刷新有最短间隔；暂停查询会跨重启保留，不改变网络守护。历史快照标注时间；重置时间到期不会自行填充为 100%。

Codex 使用本机官方 CLI 的 app-server 账号额度接口，不创建会话、不调用模型，不读取或复制其账号文件。它使用普通网络，与 Claude 的专用通道独立。账号 RPC 错误显示暂不可用并保留历史额度；空账号会复查一次，仅在服务明确返回需要登录时提示。Codex 登录后会按正常轮询恢复，刷新中不再显示上一轮的未登录提示。

Claude 仅在 TUN、固定出口、守护身份和有效租约全部通过时查询。本机辅助进程经 macOS sandbox-exec 限制，只能访问守护状态端口和指定入口；同时显式使用受控 CONNECT / TLS，无直连或备用代理。不支持隔离时查询失败，不解除限制。复用本机 Claude Code 钥匙串中的有效访问令牌到内存，不自行交换刷新令牌，不写入日志或面板缓存。短期访问令牌到期时，在相同网络隔离下启动官方 Claude Code CLI，由它维护自己的登录；不发送提示词、命令或模型请求，禁用用户配置、插件、MCP 和工具，完成或超时即终止。更新失败显示“登录待同步”，保留手动登录入口，不将桌面端已登录等同于 CLI 令牌有效。查询使用的个人订阅接口并非公开稳定 API，第三方认证的支持范围仍受 Anthropic 条款约束。

公司卡片提供独立 WebKit 登录空间；公司 HTTPS 请求通过本机受限 relay 使用办公网络，只允许公司域名、443/7799 和内网地址。页面必需的 static1.tuyacn.com、cdnjs.cloudflare.com 资源仅经已存在的本机普通代理加载，代理不可用时拒绝，不回退公网直连。不修改系统代理，不经过 Claude 通道。首次须用户自行完成 SSO。主动查询先在 WebKit 内通过 `/api/da/v1/user/me` 验证会话，并在隔离的 JavaScript 内存中取得公司要求的 CSRF 头；不会导出到原生层或写入面板缓存。随后沿用公司前端的两个只读 GET 接口 `/api/da/v1/coding-plan`、`/api/da/v1/quota/personal-summary`，仅返回额度百分比和实际提供的重置时间；Cookie 和登录状态保留在 WebKit，不导出到 Node 或面板缓存。右键卡片可断开并清除本功能自己的公司登录。

用量缓存位于 `usage-snapshots.json`，仅含显示数据，权限为 0600，不含令牌或对话。不能将本功能的进程隔离理解为所有应用都不会绕过系统代理。

已移除多账号切换、登录收录和快照导入功能。GuardNook 不再读取或替换 Claude 的登录数据目录。旧版遗留的本地账号存档保持原样，不自动删除。Claude 登录与退出请在 Claude Desktop 中完成。

## 日志与诊断

日志页记录面板运行期间观察到的守护变化、网络检测、环境检查与配置操作。支持搜索、类别/级别筛选、复制、导出和确认后清空。自动轮询状态未变化时不重复记录。

最近 1,000 条存放在 ~/Library/Application Support/GuardNook/Logs/events.json，目录 0700、文件 0600。写入和导出脱敏 IP、邮箱、用户主目录及常见凭据格式；不采集账号令牌、Cookies、配置对象或聊天内容。历史文件读取失败时原文件保留，当前日志暂存内存并提示。

设置中的“导出脱敏诊断包”包含版本、系统版本、检查状态与脱敏日志，排除账号名称、配置对象、节点订阅、凭据和聊天内容。

## 更新、回退与卸载

使用手动更新流程，不包含 Developer ID / Apple 公证流程，也没有自动下载安装。下载可信来源的新版本和附带的 verification.json，在设置中选择“校验新安装包”，核对 SHA-256；此校验只说明完整性，不证明发布者身份。继续后备份当前程序，再打开安装包手动替换；打开前重新校验文件，防止校验后发生变化。

程序备份位于 Backups/update-*。需要回退时退出应用，将备份中的 GuardNook.app 手动恢复到应用程序。本机配置保存在程序包之外；回退程序不会自动回退数据格式，升级前应保留相应数据备份。

卸载前按需恢复环境更改，使用“解除连接 / 准备卸载”保存连接恢复点。本应用管理的通道会先置为 REJECT；接着在代理客户端恢复原始扩展脚本并重载，以撤销已安装规则，再关闭开机启动、退出并移除应用。可以通过“恢复上一次连接”找回配置，恢复后需明确启用并重新验证。本地日志、环境备份和旧版遗留存档保留供用户手动处理，不会随解除连接删除。

连接已有独立守护时，解除只停止本面板连接，原守护继续运行。原服务的卸载与分流恢复需要使用原服务的恢复流程，GuardNook 不擅自卸载它。旧版备份与当前独立服务均保持原有所有权。

## 固定出口守护边界

保护规则、冻结链路、出口租约与实时验证保持失败关闭。显式 publicTunExit/publicProxyExit 可让 TUN 或普通代理入口的公网 TCP 优先走固定链路，保留用户定义的公司内网和局域网例外。生成规则不自动开启系统代理，也不把所有应用宣称为已接管。

本机可选的 codex-intranet.json 扩展支持公司网段、DNS、接口和应用例外，默认不启用，不内置任何公司的参数。需要用户提供自己的真实配置，不随发布包分发。

## 源码构建与导出

需要 macOS、Swift / Xcode Command Line Tools、Python 3。服务测试需要 Node.js 22+。所需 OpenNook 模块已包含在 Vendor 中，无需原主工程。

```sh
swift build
sh Tests/run-log-checks.sh
sh Tests/run-network-checks.sh
sh Tests/run-launcher-checks.sh
sh Tests/run-todo-checks.sh
sh Tests/run-resource-checks.sh
node --experimental-strip-types --test Service/claude-guard/*.test.mjs
python3 Scripts/package-macos.py --output dist --version 0.4.0
python3 Scripts/export-release.py --output ~/Downloads --version 0.4.0
```

打包脚本构建 Apple 芯片和 Intel 的 Universal 应用，收进固定版本并校验 SHA-256 的官方 Node.js 运行时，首次打包需要联网。导出脚本只收集源码白名单，不打包用户数据、缓存、历史备份或凭据，输出 DMG、应用 ZIP、独立源码 ZIP、校验文件和合集。

项目及第三方许可证位于 LICENSE、Vendor/OpenNook 和 Service/claude-switcher。环境检测设计参考 Claude Switcher 的 MIT 实现，归属说明随应用分发。历史个人出口示例已改为文档示例地址，使用时必须配置自己的节点和真实出口。

Clash 扩展脚本兼容性：本机 Clash Verge 2.5.3 的 Boa 引擎曾在配置重载时发生原生 Set 迭代器回收崩溃，导致扩展输出被丢弃。生成器现将数组实现的 Set 限定在 Guard 转换器内部，保留集合去重与遍历行为，不改写宿主或其他脚本的全局对象。配置仍须通过 Mihomo 验证、冻结链路与固定出口连续校验后才放行。

保护域名和已启用的公共固定出口使用两组 HTTPS DNS，均显式绑定同一个冻结出口，不增加直连后备。公司域名的专用 DNS 保持优先；与企业 VPN 共用 TUN 时，需同时确认 Clash 核心配置及扩展输出保留实际的私网路由排除，避免核心设置覆盖扩展结果。企业域名与网段只保存在本机配置，不写入发布包。
