# Claude Guard for MetaCubeXD

在 Mac 的当前用户账户全局运行的守护服务。源码项目只是开发位置；安装后的代码、网页与配置位于 `~/Library/Application Support/ClaudeGuard`，启动项位于 `~/Library/LaunchAgents/local.claude-egress-guard.plist`，应用入口位于 `~/Applications/Claude Guard.app`。关闭项目、Codex 或面板不会停止守护。登录后由 launchd 自动启动并在意外退出后重启。

## 三条路径

- Claude：Clash 原有 Claude 组只含 `REJECT` 和本地守护网关。网关验证唯一出口 `<IP>` 后放行，否则关闭现有隧道并阻断新连接。
- 普通网页：原有 Clash 全局规则与代理组。
- 内网：原有公司 VPN、DNS 和内网规则。

保留 Google 登录和验证码的已有路由，避免再次改变登录路径；不增加独立登录/验证码探测。不卸载 Claude，不改账号、历史、Skills、Hooks、插件或 CC Switch。

## 运行与安装

```sh
node --test apps/claude-guard/*.test.mjs
MCXD_DISABLE_PWA=true pnpm --filter @metacubexd/ui exec nuxt prepare
MCXD_DISABLE_PWA=true pnpm --filter @metacubexd/ui generate
node apps/claude-guard/install.mjs
```

安装默认只观测，**不会修改当前 Clash 配置或宣称已保护**。安装器备份原脚本并生成私有 `prepared-Script.js`，生成配置与脚本权限为 0600。重载前应验证 Mihomo 配置，并核对差异只涉及指定组、守护代理、探测入站、7901 入站、Claude/现有 Google 路由。

本机接入命令为 `node apps/claude-guard/deploy.mjs`：先验证当前脚本与备份一致、离线测试生成的 Mihomo YAML，再备份运行配置，选择 REJECT、原子写入脚本并重载，最后启用全局启动项的强制验证。失败恢复原文件，并尽力保持 Claude 阻断。该命令针对本机现有 Clash Verge 路径及 pinned 规则，不能用于未审核的其他电脑。

载入生成脚本后，面板“启用保护”从阻断状态开始，连续三次通过才放行。将启动项增加 `--enforce` 可在每次登录时自动开始验证。启动时及服务不存在时网关关闭。手动“阻断 Claude”写入私有状态文件，重启后仍保持阻断，直到主动启用。损坏的状态文件也保持阻断。

服务只监听 loopback：面板 17891、网关 17904，Clash 私有探测入站 17903。探测入站与网关均要求每次安装生成的本地代理凭据。凭据与现有代理备份不要上传 GitHub。

## 安全与边界

本机现启用 `requireTun: true`：只有 Clash 控制接口确认 `tun.enable === true`，固定出口和代理链连续验证成功，网关才会开放。关闭 TUN 或无法确认其状态会清零连续成功次数、关闭网关和已建立的网关连接，并清理内核可识别的 Claude 连接；重新开启 TUN 仍须重新验证。TUN 状态每 250 毫秒检查一次，单次读取有 700 毫秒超时，因此切换到阻断存在有限响应时间。配置保存和节点切换保留本机的 TUN 要求，不因更换节点解除它。旧安装未设置此项时保持兼容，不能把本机行为当作旧版本已经具备的能力。

本机 `guardGoogleAuth: false`，Google 搜索和账号域名不进入 Claude 专用网关，恢复原普通网络路径，避免关闭 TUN 时连带阻断 Google。Claude 桌面进程的规则和 LuLu 限制仍保留；浏览器中的 Google 登录是共享流量，不能仅凭域名区分它用于 Claude 还是其他网站。Claude 主站和回调访问仍受 TUN 条件约束。旧配置默认保留原 Google 路由契约，重新配置本机节点时保留这个 Google 例外。

本机内网扩展的 `corporateDomains: ["corp.example.com"]` 让公司域名使用公司 DNS、真实地址和指定 VPN 接口；公司网段也绑定该接口。规则位于 Claude 强制保护规则之后、公网 TUN 规则及普通 DIRECT 网段之前，避免被固定公网出口或普通接口接管。公司域名不是全局直连例外，不能覆盖受保护的 Claude 域名。配置重载脚本保留这些显式内网设置。

此条件约束守护网关和 Clash 已接入的 Claude 域名、进程及登录依赖；它不是 macOS 全局网络过滤器。完全绕过代理的程序仍需 LuLu 等系统过滤规则，浏览器中共享服务的请求也不能仅凭共享域名归属 Claude。当前本机保留原有 LuLu 规则和 Codex 内网例外。

新连接在已有短租约内检查 TUN、控制接口和完整分流规则，不再先等待一次额外的公网出口探测。这个准入检查不能签发或续期租约，也不增加成功次数；过期、手动阻断、错误出口或不可确认的状态均拒绝连接。后台出口检测照常执行，失败关闭和连续三次恢复条件不变。原生面板的匿名 trace / 网页观察请求各等待最多 12 秒，避免把较慢的双层代理连接误判为 6 秒超时；面板的等待时间不改变守护放行条件。

每 3 秒串行检测，通过匿名 `https://claude.ai/cdn-cgi/trace` 获取出口，并检查当前连接源端口、入站与 pinned 代理链。使用 TLS 正常证书校验，不读取登录 Cookie 或进行 Claude 账号/API调用。失败立即关闭网关；检测结果最长有效 20 秒，即使控制接口失联也会关闭。恢复需连续三次成功。

远端 IP 在两次检测之间变化仍有有限检测窗口；同一 IP 的一次检测不能证明所有将来请求的出口。服务不承诺捕获绕过 Clash 的浏览器、系统网络扩展或其他 VPN。因此应保留现有 LuLu、Clash TUN、PAC、浏览器代理及 WebRTC 约束。切换 Clash 全局/直连模式或外部修改路由会使守护关闭，但外部工具主动绕开规则不能仅靠面板防止。

MetaCubeXD 桥接只读，不允许全局模式、代理选择、订阅更新或任意 URL 请求写入。普通节点选择仍可在原 Clash 客户端完成。状态 API 不输出令牌、请求头、正文或 URL 查询；连接记录另包含 Clash 提供的进程、路径和来源地址，仅由本地接口提供。

## 网络体检

### 可选的目标地址限制

`gatewayAllowlist` 默认为 `null`，保留原有代理行为。设置为域名数组后，网关只允许这些域名及其子域的 HTTPS 443 连接；空数组拒绝所有目标。IP 字面量、本机回环、内网域名及未列出的域名都会在解析和上游连接之前被拒绝。此限制与出口租约、TUN 条件同时生效。

在自有保护模式下，受限客户端端口由 Node 过滤网关直接监听，Mihomo 不再监听该端口。不能先经过普通 Mihomo HTTP 入站再依靠 `proxy` 字段限制目标，因为普通路由中的 localhost / DIRECT 例外可能使请求绕过目标过滤。普通浏览器代理端口和公司的分流规则保持独立。

该功能限制进入网关的连接。绕过代理的应用及其子进程还需要系统防火墙；LuLu 的进程树规则有进程归属和父进程存活方面的边界，不等同于操作系统沙箱。已经授权的屏幕、文件、外部浏览器和 MCP 工具也需要分别管理。

面板现为 Claude 专用单页，首页只显示连接判断、固定出口、通道状态、环境检查和一键检查。安装后的首页及旧概览/代理/流量等地址都转到 `/claude-guard`，不再显示通用 Clash 菜单。域名、DNS 和连接记录收进同一个详情折叠区；普通代理管理仍由用户在 Clash 客户端进行。

“受控连接已验证”要求守护状态新鲜且有效、网页/API 两个实际客户端检测均在 5 分钟内通过、DNS/UDP 配置核验通过且没有观察到异常。面板超过 5 秒没有取得当前守护状态、客户端检测过期或环境数据未确认时，不显示已就绪。此判断仅给出使用建议，不修改守护放行条件。浏览器 DNS/WebRTC 实时旁路未验证时继续单独提示，不把推荐设置当作账号登录安全证明。

面板增加域名覆盖表、受保护 DNS 配置、Ego Lite 推荐 WebRTC 设置、Claude UDP 配置、当前内核可见旁路和最近 60 次 HTTPS 检测耗时。体检每分钟只读更新，超过两分钟的结果显示未知。DNS / 浏览器设置仅是配置证据，不代表实时泄漏检测通过。RoxyChrome 应在自己的窗口中打开检测入口；面板不读取浏览器登录数据，也不收集 Canvas / WebGL 指纹。

“检测出口与代理链”只对三个固定主机，通过已有 7901 入口发送匿名 HTTPS trace，不发送 Cookie / API 凭据，不跟随重定向，不接受任意主机输入。trace 未返回 IP 与网络失效分开显示；检测结果带时间，不替代持续守护的有效租约。辅助体检的失败不切换代理、不阻断 Claude。普通网页可以使用独立路径和不同出口。

域名目录以 Claude Code 官方 network-config 为基准，保留 Net.Coffee 的部分待确认参考项。共享 SaaS / 关键词、ASN / IP 段和 NTP 不自动写入配置；NTP 同步 UTC，不能从 NTP 返回值推断地理时区，WebRTC 测试也不能验证所有 UDP。第三方评分不用于自动放行，不预测账号安全。页面提供外部检测入口，仅由用户主动打开。


原生面板的最近网关连接每秒只读采集 Clash 连接表，按连接唯一 ID 保留最近 40 条，展示最新 3 条。进程名及路径来自该连接的原始客户端元数据，不按域名猜测应用；私有探测端口的转发连接不计入。缺少进程信息时展示实际来源 IP 和端口，可悬停查看完整证据。自动探测可能出现在记录中，一秒内结束的连接可能未被采集；控制接口失联时历史记录仍保留，但不标成活跃连接。

## 故障与退出

面板显示“未接入/仅观测/未知”均不能当作保护成功。`launchctl print gui/$(id -u)/local.claude-egress-guard` 可查询当前用户服务。

停止服务会使已接入的 Claude 通道保持失败关闭，普通/内网规则仍由 Clash 运行。撤销部署应先保持 Claude 阻断，再从安装备份精确恢复原 Clash 脚本并重载，最后移除启动项与应用；不要在恢复步骤中加入 DIRECT 或备用国家出口。
